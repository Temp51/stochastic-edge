Markov Chain Market Regime Detection: Hidden Markov Models in Python

The market isn't one process — it's several different processes wearing the same ticker symbol. The problem is you never see which one is currently running, only its output. That's not a simple Markov chain problem. It's a hidden one.

∞
The Stochastic Edge
July 9, 2026 · — min read

A strategy backtested over five years of calm, low-volatility markets will fail the first month a real crisis hits — not because the strategy was wrong, but because it was fit to one regime and deployed into another. Volatility clustering, trending vs. mean-reverting behavior, correlation breakdowns during crashes: these aren't noise around a single stationary process. They're evidence that the process itself is switching.

Regime-aware modeling starts from that premise directly. This article builds the actual machinery for it: Markov chains as the underlying concept, then the honest complication that makes plain Markov chains insufficient for markets, then the model that actually gets used in practice.

📐
What you'll need: Python 3.9+, numpy, and hmmlearn — the standard library for this. pip install numpy hmmlearn yfinance

Markov Chains: The Underlying Idea

A Markov chain describes a system that moves between a finite set of states, where the probability of the next state depends only on the current state — not on the full history that led there. Formally, for states {1, ..., S}:

P(Z_{t+1} = j | Z_t = i, Z_{t-1}, ..., Z_1) = P(Z_{t+1} = j | Z_t = i) = a_ij // a_ij = transition matrix entry: probability of moving from state i to j // This "memorylessness" is the Markov property. It's a strong, testable // assumption — and a genuinely useful approximation for regime dynamics, // where "how you got to a bear market" matters much less than "you're // currently in one."

If market regimes were directly observable — if every day came pre-labeled "bull" or "bear" — this would be the whole model. Estimate the transition matrix from labeled history, done. That's not the situation you're actually in.

The Complication Almost Everyone Glosses Over: Regimes Are Hidden

You do not observe "which regime the market is in." You observe returns. The regime is a latent variable that you have to infer from the pattern of returns it's producing — different means, different volatilities, different persistence. This is precisely the setting a Hidden Markov Model (HMM) was built for: a Markov chain running on an unobservable state sequence, where each hidden state emits observable data according to its own probability distribution.

// HMM structure for S hidden regimes over T observed return periods: Z_t ∈ {1, ..., S} // hidden regime at time t (NOT observed) R_t // observed return at time t δ_i = P(Z_1 = i) // initial regime distribution a_ij = P(Z_{t+1} = j | Z_t = i) // transition matrix (as above) b_i(r) = P(R_t = r | Z_t = i) // emission distribution per regime ~ Normal(μ_i, σ_i²) // Gaussian HMM: each regime has its // own mean and volatility of returns

A 2-regime Gaussian HMM fit to equity returns typically recovers something intuitive without ever being told to look for it: one state with a small positive mean and low variance (call it "calm/bull"), and one state with a mean near zero or negative and noticeably higher variance ("volatile/bear"). The model isn't told these labels — it discovers the clustering structure in the data and you name the states after the fact by inspecting their fitted parameters.

Fitting the Model: Baum-Welch and Viterbi

Two algorithms do the actual work, and it's worth knowing what each one answers:

  • Baum-Welch (a specific case of Expectation-Maximization) — answers "given the observed returns, what transition matrix and emission parameters best explain this data?" This is the fitting/training step.
  • Viterbi — answers "given a fitted model, what is the single most likely hidden-state sequence that produced this exact data?" This is the decoding step — it's what actually tells you "day 340 was almost certainly Regime 2."

In practice, you don't hand-implement either — hmmlearn's GaussianHMM class runs both under the hood: .fit() calls Baum-Welch, .predict() calls Viterbi.

Full Python Implementation

python 
import numpy as np
import pandas as pd
import yfinance as yf
from hmmlearn.hmm import GaussianHMM


def fit_regime_model(returns: np.ndarray, n_regimes: int = 2, seed: int = 42):
    """
    Fit a Gaussian HMM to a return series and decode the most likely
    regime for every historical period.

    returns   : (T,) array of period returns (e.g. daily log returns)
    n_regimes : number of hidden states to fit. 2 (bull/bear) or 3
                (bull/chop/bear) are the standard practical choices.

    Returns: (model, hidden_states) where hidden_states is a (T,)
    array of the Viterbi-decoded regime label for each period.
    """
    X = returns.reshape(-1, 1)  # hmmlearn expects 2D: (n_samples, n_features)

    model = GaussianHMM(
        n_components=n_regimes,
        covariance_type="full",
        n_iter=1000,
        random_state=seed,
    )
    model.fit(X)                        # Baum-Welch: estimates A, means, variances
    hidden_states = model.predict(X)    # Viterbi: decodes the state sequence

    return model, hidden_states


def describe_regimes(model: GaussianHMM):
    """Print the fitted mean/vol per regime and the transition matrix."""
    print("Transition matrix (rows = from, columns = to):")
    print(np.round(model.transmat_, 3))
    print()
    for i in range(model.n_components):
        mean = model.means_[i][0]
        var  = model.covars_[i][0][0]
        print(f"Regime {i}: mean={mean*252:.1%} annualized, "
              f"vol={np.sqrt(var*252):.1%} annualized")


# ── Example: fit on real S&P 500 daily returns ────────────────────────
data = yf.download("^GSPC", start="2015-01-01", progress=False)
log_returns = np.log(data["Close"] / data["Close"].shift(1)).dropna().values

model, states = fit_regime_model(log_returns, n_regimes=2)
describe_regimes(model)

# Most recent regime classification
current_regime = states[-1]
print(f"\nMost recent trading day classified as Regime {current_regime}")
ℹ
Reading the output: regimes are returned as integers (0, 1, ...) with no inherent meaning — describe_regimes() exists specifically so you assign the "bull"/"bear" label yourself, after seeing which fitted mean/variance pair corresponds to which number. Don't hardcode the label before fitting; let the data tell you which index is which.

Choosing the Number of Regimes

Two is the honest starting point — it's identifiable, interpretable, and hard to overfit. Three (adding a "choppy/transitional" middle state) is common in practice and often fits real equity data noticeably better. Beyond three, use an information criterion rather than intuition:

BIC = −2·ln(L̂) + k·ln(T) // L̂ = maximized likelihood, k = number of free parameters, T = obs count // Fit models with 2, 3, and 4 regimes; the BIC penalizes extra states // unless they earn their keep in likelihood. Lower BIC wins. // hmmlearn exposes model.score(X) → log-likelihood, so BIC is a few // lines to compute directly from the fitted models.

Where This Breaks — Said Plainly

  • Look-ahead bias is easy to introduce by accident. model.fit() on the full history and then evaluating regime accuracy on that same history is fitting and grading on the same data. A real backtest re-fits (or at minimum re-decodes) using only data available up to each point in time.
  • The model assumes regimes are genuinely Markovian and Gaussian-emitting. Real markets have fatter tails and more structure than a Gaussian HMM captures. It's a useful approximation, not a claim about the true data-generating process.
  • Regimes detected in-sample are not the same as regimes predicted out-of-sample. Viterbi decoding on historical data tells you what already happened with the benefit of hindsight across the whole series. Real-time regime classification (predict on data up to today only) is a harder, noisier problem — expect more label-flipping near genuine transition points.
  • Non-stationarity is the deepest issue. Even the regimes themselves may not be stable across decades — a "bear market" fitted on 2008 data and one fitted on 2000 data don't necessarily share the same statistical fingerprint. Refit periodically rather than treating one historical fit as permanent.

Key Takeaways

  1. A plain Markov chain assumes regimes are observed. Markets never hand you that — you only ever see the emissions (returns), never the hidden label. That gap is exactly what an HMM is for.
  2. Baum-Welch fits, Viterbi decodes. Two different questions, two different algorithms, both wrapped inside hmmlearn.GaussianHMM.
  3. Let the fitted parameters name the regimes — never hardcode which integer means "bull" before inspecting means_ and covars_.
  4. The honest failure modes matter as much as the model — look-ahead bias, non-stationarity, and the Gaussian assumption are where naive implementations quietly go wrong.

This model becomes genuinely useful the moment it's connected to something downstream that changes behavior based on the detected regime — which is exactly what regime-conditional Kelly sizing does with the position-sizing formula from the previous article: recompute μ and σ within each detected regime instead of blending them across regime changes the model exists to detect in the first place.
